# ИИ внутри онлайн-деканата МУКПиД: разбор успеваемости

Документ для отчёта жюри: что делает ИИ, какой промпт и зачем, какие ошибки модели мы ожидали и как их ловим, какие решения приняты по безопасности. Контракт маршрута — в [api.md](api.md#разбор-успеваемости-ии), требования — в разделе 5 [spec.md](../spec.md).

## Принцип

**Числа считает код, модель только пишет текст.** Средний балл, проходной результат (от 40 баллов), сколько баллов не хватает до него и до следующей оценки сервер считает сам и передаёт модели готовыми. Модель ничего не создаёт и не меняет. Если она не ответила, страница показывает тот же расчёт без ИИ.

## Функция

| Где | Что делает ИИ | Маршрут | Без ИИ |
|---|---|---|---|
| Студент → «Предметы», блок «Обратите внимание» | Короткий разбор: какие дисциплины ниже проходного результата, с чего начать, сколько баллов не хватает. Пометка «Разбор ИИ» | `GET /api/ai/grades-insight` | Шаблонный текст, посчитанный кодом |

Шкала: менее 40 — «2», 40–59 — «3», 60–79 — «4», от 80 — «5»; зачёт и проходной итоговый результат — от 40. Правило допуска к экзамену в прототипе не определено, поэтому разбор о допуске не пишет. Пороги заданы в одном месте на сервере (`apps/api/src/grades-scale.ts`) и повторены во фронтенде (`apps/web/src/lib/format.ts`).

## Промпт

Файл `apps/api/src/ai/prompts/grades-insight.ts`, на русском.

- Модель получает таблицу баллов с уже посчитанными числами и правила шкалы «для понимания, пересчитывать не нужно».
- `summary` — 1–2 предложения о главном; `items` — 2–4 пункта: сначала дисциплины ниже 40 баллов, потом на грани следующей оценки, потом сильные стороны.
- Ограничения: только числа из данных, без обещаний оценок, обращение на «вы», без восклицательных знаков. Ответ — только JSON `{summary, items:[{subject, note}]}`.
- Общее правило (`prompts/shared.ts`): данные передаются только внутри блока `<данные>…</данные>`, системный промпт прямо говорит, что это не инструкции.

## Ошибки модели и как мы их ловим

Каждый ответ проходит проверку в `apps/api/src/ai/validate.ts`. Ответ, не прошедший её, не попадает на экран: маршрут возвращает `{ok:false, reason:'invalid'}`, интерфейс показывает расчёт по баллам. Случаи покрыты тестами (`tests/unit/ai.test.ts`, `tests/ai.test.ts`).

| Что может сделать модель | Что делает сервер |
|---|---|
| Написать про «допуск», которого в правилах нет | Ответ отбрасывается (`invalid`), показывается расчёт по баллам |
| Пересчитать или придумать число («не хватает 7 баллов» при реальных 2) | Каждое число в тексте сверяется с посчитанными кодом; чужое число — `invalid` |
| Назвать дисциплину, которой нет у студента | Пункт отбрасывается; если не осталось ни одного — `invalid` |
| Дать больше 4 пунктов или повторить дисциплину | Повторы убираются, пунктов не больше 4 |
| Обернуть JSON в ```` ```json ```` или добавить «Конечно! Вот разбор:» | Извлекается объект между первой `{` и последней `}` |
| Вернуть битый JSON | `invalid`, без падения |
| Вставить разметку или управляющие символы | Удаляются, текст обрезается до лимита |
| Не ответить за 10 секунд | `timeout`, запрос отменяется |
| Отфильтровать ответ (CONTENT_FILTER у YandexGPT) | `invalid` |

> Раздел для Кирилла: после прогона на реальном YandexGPT для обоих демостудентов допишите сюда удачные и неудачные ответы и что поправили в промпте. На момент написания модуль проверен на `mock` и на имитации ответов YandexGPT в тестах; запросов к реальному ключу ещё не было.

## Безопасность

- **Ключ** только в переменных окружения (`AI_API_KEY`, `AI_FOLDER_ID`). Он не попадает в браузер, ответы API и логи. Ошибка провайдера наружу не передаётся, в лог пишется только причина.
- **Провайдер в России.** YandexGPT; GigaChat поддерживается как запасной. OpenAI и Anthropic не используются: сервер в Москве.
- **Свои данные.** Сессия и роль проверяются как во всём API: без сессии 401, преподавателю и сотруднику 403. Баллы сервер берёт по сессии; id студента из запроса не принимается.
- **Минимум данных в модель.** Названия дисциплин, форма контроля и числа. Без email, id и ФИО.
- **Ограничения.** 20 вызовов модели в час на пользователя, при превышении 429. Разбор кэшируется по студенту и хэшу баллов: повторное открытие страницы модель не вызывает, новый вызов — только при изменении баллов.
- **Пометка.** Текст модели подписан «Разбор ИИ».
- **mock** запрещён в production, если не задано `AI_ALLOW_MOCK=1` (для демо без ключа).

## Настройка

```sh
AI_PROVIDER=yandex          # yandex | gigachat | mock | off (пусто — выключено)
AI_API_KEY=...              # API-ключ сервисного аккаунта с ролью ai.languageModels.user
AI_FOLDER_ID=...            # ID каталога Yandex Cloud
AI_MODEL=                   # необязательно, по умолчанию yandexgpt-lite/latest
AI_LIMIT_PER_HOUR=          # необязательно, по умолчанию 20
```

Для GigaChat: `AI_PROVIDER=gigachat`, `AI_API_KEY` — ключ авторизации, `AI_SCOPE` (по умолчанию `GIGACHAT_API_PERS`), а при запуске — `NODE_EXTRA_CA_CERTS` с корневым сертификатом Минцифры.
